# HookLens UI 개편 설명서

작성일: 2026-10-20  
기준: 내부 로직 보완본과 첫 UI 개편의 배치를 유지하고, 글자만 소폭 확대한 버전  
최신 변경: [9. 기존 배치 유지와 글자 소폭 확대](#9-기존-배치-유지와-글자-소폭-확대)

## 1. 선택한 레이아웃과 참고 자료

선택한 구성은 **상단 요약 + 왼쪽 엔드포인트 목록 + 오른쪽 상세 작업 영역**이다.
입력 화면과 결과 화면을 분리하고, 결과에서 코드·시험 근거·수정 방향을 순서대로 확인하게 했다.

| 참고 자료 | 검토한 구성 | 프로젝트에 적용한 내용 |
|---|---|---|
| [GitHub Code scanning alerts](https://docs.github.com/en/code-security/how-tos/manage-security-alerts/manage-code-scanning-alerts/assess-alerts) | 검색 가능한 경고 목록, 경고 상세, 코드 위치와 해결 안내 | 엔드포인트 검색·필터, 파일·줄 위치, 원본 코드 문맥과 탐지 줄 강조 |
| [Sentry Issue Details](https://docs.sentry.io/product/issues/issue-details/) | 상단 핵심 정보와 이슈별 상세 정보의 분리 | 결과 요약 카드와 선택한 엔드포인트의 상세 탭 구성 |
| [Stripe Workbench event destinations](https://docs.stripe.com/workbench/event-destinations) | 이벤트 전달 목록, 전달 상태, HTTP 응답과 시도 내역 | 정상 요청 기준 4단계, 동적 시험 상태·변형·HTTP 코드·실행 근거 표시 |

GitHub 문서의 경고 목록·상세 스크린샷과 Stripe 문서의 등록 화면도 확인했다.
Sentry는 공식 문서 검색에서 제공된 정보 구성을 참고했다. 해당 상세 페이지의 직접 열기는 콘텐츠 형식 오류로 완료되지 않았다.
타사 화면·로고·이미지·스타일시트를 제품에 복사하지 않았다. 화면은 프로젝트에 맞게 새로 작성했다.

세부 디자인은 남색 내비게이션, 밝은 회색 작업 배경, 흰색 카드, 파란색 주요 동작으로 구성했다.
등급과 시험 상태에만 의미 있는 색을 사용한다. 외부 폰트·이미지 CDN·JavaScript 패키지 없이 동작한다.

## 2. 유지한 분석 범위

- Python 지원, `.py` / `.zip` 입력.
- 정적 규칙 WHSEC-001~005의 5개 규칙.
- 다운그레이드·서명 정책 / 재전송 / 타입 혼동·입력 정책의 동적 3개 시나리오.
- AST → 플랫폼 감지 → SAST / DAST → 리포트 흐름.
- Probe 4단계와 Tier 1 / Tier 2.
- 기존 `/analyze` 입력 필드, 탐지 결과·판정 조건·점수·플랫폼별 서명 처리.

`analyzer/`의 분석 모듈, `main.py`, `requirements.txt`, 테스트 수신 서버와 샘플 코드는 이번 UI 작업에서 변경하지 않았다.

**CVSS 관련 기준은 이번 UI 작업으로 해결하거나 변경하지 않았다.**
앞선 보완본과 같이 화면에서는 ‘규칙 참고 위험도’로 표시한다.
포스터의 CVSS 명칭과 산출 근거를 일치시키는 작업은 별도로 남아 있다.

## 3. 입력 화면

### 코드 선택

- 클릭·드래그 앤 드롭으로 Python 또는 ZIP 파일을 선택한다.
- 선택한 파일명·크기를 표시한다.
- `.py` / `.zip` 이외 확장자, 빈 파일, 10 MiB 초과 파일을 클라이언트에서도 확인한다.
- 서버의 업로드 검증은 기존대로 유지한다.

### 분석 방식

‘정적 + 동적 분석’과 ‘정적 분석만’을 명시적으로 선택한다.
정적 분석만 선택하면 동적 설정 입력은 숨기고 비활성화해 전송에서 제외한다.
동적 분석에서는 HTTP(S) 수신 서버 기본 URL을 입력한다.

시크릿은 기본적으로 가린다. 표시 전환 버튼을 제공하며, 브라우저 저장소나 결과 JSON에 폼의 키를 별도로 넣지 않는다.

### 고급 설정

상태 생성·조회 경로, 타임스탬프 허용 시간, JSON 객체 전용 정책을 접힌 설정으로 모았다.
상태 경로는 쌍으로 입력하며, 조회 경로에는 `{id}`가 있어야 한다.
JSON 객체 전용 옵션의 의미와 시험에 필요한 키의 역할을 화면에서 설명한다.

### 시연 설정

버튼을 누르면 아래 **설정값만** 채운다.

| 항목 | 값 |
|---|---|
| 서버 URL | `http://127.0.0.1:8000` |
| 데모 시크릿 | `dku-toss-secret-2026` |
| 상태 생성 | `/orders` |
| 상태 조회 | `/orders/{id}` |
| 허용 시간 | 300초 |
| JSON 객체 전용 | 선택하지 않음 |

`샘플 파일 선택`, `수신 서버 실행`, `분석 시작`은 사용자가 수행한다.
결과를 미리 채우거나, 서버를 자동 실행하거나, 가짜 분석 결과를 보여주는 버튼이 아니다.

## 4. 결과 화면

### 전체 요약

파일명, 분석 방식, 소요 시간, 종합 등급을 표시한다.
정적 위험 징후·동적 처리 증거·수락 관측·판단 불가·생략을 구분한다.
‘추가 확인’의 큰 숫자는 수락 관측과 판단 불가의 합계이며, 생략 건수는 아래에 별도로 표시한다.

### 엔드포인트 목록

- 경로와 플랫폼으로 검색한다.
- 모든 결과 / 위험 징후 있음 / 동적 처리 증거 / 추가 확인 필요로 필터링한다.
- 목록에서 선택하면 오른쪽 상세 내용이 바뀐다.
- 필터에 해당하는 결과가 없으면 이전 상세 결과도 지워 혼동을 줄인다.

### 상세 탭

| 탭 | 내용 |
|---|---|
| 분석 요약 | 정상 요청 기준, 정적 탐지 항목, 동적 3개 시나리오 요약 |
| 정적 분석 | 규칙, 설명, 실제 파일·줄, 주변 원본 코드와 탐지 줄 강조, 수정 방향 |
| 동적 시험 | 시험군·변형, 판정 상태, HTTP 코드, Tier, 신뢰도, 실제 실행 근거 |
| 수정 가이드 | 권고와 참고 코드, 복사 버튼, 공식 참고 문서 |

SAST-only 결과에는 동적 Tier 2 관측을 수행한 것처럼 표시하지 않는다.
서명 오류·연결 오류 등의 미완료 상태를 안전 결과로 바꾸지 않는다.
API가 보내지 않는 원시 요청 본문이나 `pending → paid`의 구체적인 전후 값은 임의로 만들지 않는다.
현재는 실제로 기록된 `state_changed`와 실행 근거를 표시한다.

### 내보내기와 인쇄

JSON 버튼은 실제 API 결과를 파일로 내려받는다.
인쇄용 내용은 현재 선택한 탭뿐 아니라 **전체 엔드포인트·정적 결과·동적 근거·수정 가이드**를 포함한다.
원본 코드와 가이드, 파일명, 실행 근거는 HTML escaping을 거쳐 표시한다.
참고 문서 링크는 HTTP(S) URL만 허용한다.

## 6. API에 추가한 표시 정보

기존 Finding 필드를 유지하고, 읽을 수 있는 업로드 소스에 아래 선택 필드를 추가했다.

```json
{
  "display_path": "security.py",
  "source_context": {
    "start_line": 8,
    "lines": ["... 실제 업로드 소스의 주변 줄 ..."]
  }
}
```

추가 처리는 `_attach_source_context()`이며, 업로드 임시 파일을 정리하기 전에 실행한다.

- 실제 탐지 파일의 앞뒤 최대 3줄, 총 최대 7줄을 제공한다.
- 줄당 표시 길이는 1,000자로 제한한다.
- 프로젝트 경계 밖 파일은 읽지 않는다.
- 외부 위임 결함은 외부 파일의 문맥을 보여준다.
- 인코딩·읽기 오류가 있으면 문맥 필드만 생략한다.
- 정적·동적 탐지 결과와 등급·위험도 산출에는 영향을 주지 않는다.

## 7. 검증 결과

프로젝트의 `requirements.txt`에 고정된 버전을 별도 가상환경에 설치해 확인했다.
환경은 Python 3.12.14, FastAPI 0.135.1, Uvicorn 0.42.0, Requests 2.32.5이다.
ASGI 검사에는 선택적 테스트 의존성 `httpx 0.28.1`을 추가했다. 제품 의존성 파일은 변경하지 않았다.

| 검사 | 결과 |
|---|---|
| Python 단위·회귀·ASGI 검사 | 63개 통과, 실패·오류 0 |
| 기존 통합 스크립트 | 22개 검사 통과, 종료 코드 0 |
| JavaScript 렌더러·입력·상태·escaping·출력 검사 | 31개 통과 |
| Python 3.10 구문 호환 | 전체 Python 소스 통과 |
| 실제 FastAPI multipart | `.py` / `.zip` 업로드와 응답 확인 |
| 실제 수신 서버 | Uvicorn으로 쇼핑몰 샘플 실행, 정상 서명 기준·만료 요청 처리 증거·잘못된 키의 판단 불가 확인 |
| 실제 브라우저 | 파일 선택, 모드 전환, 시연 설정, 코드 문맥, 검색·필터, 상세 탭, 복사, JSON 다운로드 확인 |
| 반응형 | 데스크톱과 너비 390px·높이 844px의 iframe에서 입력·결과 배치 확인 |

브라우저의 시각·상호작용 검증에는 실제 API에서 받은 결과를 내부 QA 페이지에 재생했다.
브라우저에서 파일을 전송하고 운영 ASGI 서버가 응답하는 **연속된 전체 과정**을 같은 브라우저 세션에서 검증한 것은 아니다.
실제 multipart/API 경로와 실제 수신 서버는 별도의 ASGI 검사로 확인했다.
인쇄 내용 생성·전체 항목 포함은 JavaScript 검사로 확인했으며, OS별 인쇄 대화상자·PDF 출력은 검증하지 않았다.
모바일 실기기·다른 브라우저·실제 결제 제공자 연동을 검증한 것은 아니다.
내부 QA용 버튼·재생 데이터·서버·iframe·스크린샷은 제품 ZIP에 포함하지 않았다.

## 8. 실행과 시연 순서

압축을 풀고 `app.py`가 있는 `webhook-analyzer-main` 폴더에서 실행한다.

```bash
pip install -r requirements.txt
uvicorn samples.shop_server:app --port 8000
```

다른 터미널에서:

```bash
uvicorn app:app --port 8001
```

1. `http://127.0.0.1:8001`을 연다.
2. **시연 설정**을 누른다.
3. `samples/shop_server.py`를 선택하고 **분석 시작**을 누른다.
4. 분석 요약에서 정상 요청 기준과 동적 처리 증거를 확인한다.
5. 정적 분석에서 일반 비교 코드·탐지 줄을 설명한다.
6. 동적 시험에서 만료 요청의 처리 증거를 확인한다.
7. 수정 가이드에서 수정 방향과 플랫폼 적용 조건을 설명한다.

일반 검사:

```bash
python -m unittest discover -s tests -v
python tests/test_integration.py
node tests/check_frontend.cjs
```

실제 ASGI 6개 검사를 포함하려면:

```bash
pip install httpx
python -m unittest discover -s tests -v
```

`httpx` 또는 제품 의존성이 없으면 해당 HTTP 검사 모듈은 생략된다.
앞선 내부 로직 설명서의 55개 테스트 기록은 이전 보완 단계의 기록이며, 이번 검증 수치는 위 표를 기준으로 한다.

## 9. 기존 배치 유지와 글자 소폭 확대

사용자가 처음 마음에 들어 했던 UI 개편본의 배치·화면 비율을 기준으로 삼았다.
직전에 제공한 전면 확대본은 글자 외에 아이콘·버튼·카드·간격까지 커져 화면이 답답해졌다는 피드백에 따라 되돌렸다.
최종 제품 코드 변경은 첫 UI 개편본의 화면 CSS에서 **18px 미만 글자 크기를 1~2px 키운 것**이다.
18px 이상 제목·브랜드와 결과 핵심 숫자는 첫 UI 개편본의 크기를 유지했다.

### 글자 크기

| 요소 | 처음 UI 개편본 | 최종 조정본 |
|---|---|---|
| 기본 본문 | 14px | 15px |
| 탐지 설명 | 12px | 14px |
| 입력 도움말 | 11px | 13px |
| 주요 버튼 글자 | 12px | 14px |
| 사이드바 메뉴 글자 | 13px | 14px |
| 상세 탭 글자 | 11px | 13px |
| 위험도 배지 / 탭 개수 | 9px | 11px |
| 원본 코드 / 줄 번호 | 11px / 9px | 13px / 11px |
| 결과 핵심 숫자 | 29px | 29px |
| 기본 아이콘 | 19px | 19px |

일괄적인 최소 14px 규칙을 적용하지 않았다.
기존 작은 글자는 8→10, 9→11, 10→12, 11→13, 12→14px로 조정했다.
13~17px 글자는 각각 1px 키웠다. 인쇄 전용 CSS와 동적 HTML의 인라인 크기는 처음 UI 개편본 그대로다.

### 그대로 유지한 배치

- 사이드바 기본 폭 218px, 접힌 폭 72px.
- 작업 영역 최대 폭 1,510px와 기존 바깥 여백.
- 입력·결과 카드의 패딩, 결과 목록과 상세 영역의 폭 비율.
- 아이콘 크기, 버튼 패딩, 입력창 패딩, 기존 줄 간격과 반응형 분기점.
- 기본 4열 요약 카드, 왼쪽 엔드포인트 목록과 오른쪽 상세 탭.

`min-height: 48px` 같은 전면 확대용 최소 높이나 화면 확대 비율은 추가하지 않았다.
글자가 커지면서 텍스트 줄 상자의 높이가 조금 늘어나는 것은 정상적인 브라우저 배치 결과다.

### 참고 자료

앞서 검토한 [Atlassian Typography](https://atlassian.design/foundations/typography/),
[Fluent 2 Typography](https://fluent2.microsoft.design/typography),
[Carbon Typography](https://www.carbondesignsystem.com/building-blocks/foundations/typography/overview),
[Carbon Spacing](https://www.carbondesignsystem.com/building-blocks/foundations/spacing/overview)의 글자 계층·일관된 간격 원칙은 참고하되,
크기는 사용자가 선호한 기존 화면 밀도에 맞춰 정했다. 이 자료들이 특정 최소 글자 크기를 강제한다는 의미는 아니다.

### 변경 범위와 검증

- 첫 UI 개편본의 `frontend/index.html`과 비교해 화면 CSS의 `font-size` 값 이외 부분이 동일한지 확인했다. JavaScript와 인쇄 CSS도 동일하다.
- 분석 엔진·API·샘플·CLI·의존성·테스트 파일이 첫 UI 개편본 및 전면 확대본과 동일한지 확인했다.
- 기존 JavaScript 검사 **31개 재실행 통과**.
- 브라우저에서 데스크톱 입력·결과 화면과 390px iframe의 입력·결과 배치를 확인했다.
- 데스크톱 본문 너비와 가로 스크롤 너비는 모두 1,348px, 390px iframe 내부는 모두 375px로 화면 전체의 가로 넘침이 없었다.
- 실제 API에서 기록한 결과를 내부 QA 페이지에서 재생했다. 이번에도 브라우저 업로드부터 운영 ASGI 응답까지 연결한 전체 과정이나 실제 모바일 기기는 검증하지 않았다.
- Python 63개·통합 22개는 첫 UI 단계의 기존 통과 기록이며, 이번 글자 크기 변경으로 재실행하지 않았다.
- 패치 적용과 파일 재현, ZIP 무결성을 확인했다. QA 페이지·재생 데이터·스크린샷은 제품 ZIP에 포함하지 않는다.

이번 최종 조정 기록은 `docs/verification/balanced-*`에 있다.
`readability-*` 검증 기록은 전면 확대본의 과거 기록이다.

## 10. HookLens 명칭 통일

최신 프로젝트 표기를 **HookLens**로 통일했다.
화면 배치와 글자 크기는 9절의 최종 조정본을 유지한다.

| 파일 | 변경 내용 |
|---|---|
| `frontend/index.html` | 브라우저 제목, 사이드바 이름, 하단 안내, 인쇄 리포트 제목, JSON 내보내기 파일명 |
| `app.py` | FastAPI 문서의 서비스 제목 |
| `README.md` | 프로젝트 제목 |
| `samples/shop_server.py` | 데모 화면·설명·주석의 프로젝트 이름 |
| `samples/vulnerable_zip/vulnerable_shop_server.py` | 샘플 설명·주석의 프로젝트 이름 |
| `docs/CODE_CHANGES.md`, `docs/UI_CHANGES.md` | 문서 제목과 이번 명칭 변경 설명 |

분석 모듈의 탐지·판정 조건과 5개 정적 규칙·3개 동적 시나리오, API 경로와 입력 필드, JSON 결과 스키마는 변경하지 않았다.
샘플과 API의 변경은 설명 문자열·주석에 한정된다.
브랜드 변경 전후 실행 코드를 비교하여 이름 치환과 API 문서 제목 이외 차이가 없는지 확인했다.
기존 JavaScript 검사 31개와 변경된 Python 파일의 구문 검사를 수행했다.
이번 명칭 변경에서 브라우저 시각 검증이나 Python 전체 회귀 검사를 다시 수행한 것은 아니다.

`docs/name-changes.patch`는 직전 최종 UI ZIP 대비 이름 변경 내역이다.
기존 패치는 새 결과를 기준으로 재생성했으며 패치 내부와 과거 검증 로그에는 이전 이름이 이력으로 남을 수 있다.
9절의 바이트 동일 검증은 당시 글자 조정 단계의 기록이다.
